MailLayer is published on npm as `@maillayer/core`. It runs server-side on Node 20+ and Bun 1.1+.

<PackageInstallTabs />

Import the client from the package root and each adapter from its own entry point:

```ts
import { createEmailClient } from "@maillayer/core";
import { resend } from "@maillayer/core/resend";
```

<Callout type="warn" title="Package name vs. command name">
  The package is `@maillayer/core`; the installed binary is `maillayer`. The unscoped
  `maillayer` package on npm is an unrelated project — never `npm install maillayer`.
</Callout>

## Run the CLI

<Tabs items={["Installed project", "No install (Bun)"]}>
  <Tab value="Installed project">
    Once `@maillayer/core` is in your project, the `maillayer` binary is on your path:

    ```bash
    npx maillayer adapters
    ```

    `bunx maillayer`, `pnpm exec maillayer`, and `yarn maillayer` work the same way.

  </Tab>
  <Tab value="No install (Bun)">
    For a one-off check without touching a project, point `bunx` at the scoped package:

    ```bash
    bunx --bun --package @maillayer/core maillayer adapters
    ```

    There is no safe no-install form for plain `npx` — the unscoped `maillayer` package is
    unrelated — so npm users should install first.

  </Tab>
</Tabs>

## Verify

```bash
npx maillayer version
npx maillayer adapters
```

`adapters` lists every supported provider with the environment variables it needs. To check that one provider is configured:

```bash
RESEND_API_KEY="re_..." npx maillayer doctor --adapter resend
```

## Keep credentials server-side

Provider API keys belong in environment variables (or CLI flags for one-off commands) — never in browser bundles or client-side code. The SDK is a server library by design.
