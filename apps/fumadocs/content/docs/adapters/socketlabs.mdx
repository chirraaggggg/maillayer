## Capabilities

| Repeated headers | Idempotency | Scheduling | Personalized |
| --- | --- | --- | --- |
| No | `none` | No | `expanded` |

These values come from the adapter's exported `capabilities` declaration. The [field support matrix](/docs/adapters/field-support) covers normalized message fields.

The SocketLabs adapter calls the SocketLabs injection API with plain `fetch`, so your bundle does not need the official SocketLabs SDK. It maps `cc`, `bcc`, `replyTo`, `headers`, `attachments`, and `tags` onto the provider's send payload. `metadata` is not a SocketLabs concept, so the adapter rejects it before any request is made.

## Configure

Create a SocketLabs injection API key and verify the sender identity for the account you plan to send from.

```ts title="lib/email.ts"
import { createEmailClient } from "@maillayer/core";
import { socketlabs } from "@maillayer/core/socketlabs";

export const email = createEmailClient({
  adapters: [socketlabs({ apiKey: process.env.SOCKETLABS_API_KEY! })],
});
```

## Send

```ts
const result = await email.send({
  from: "Acme <alerts@acme.com>",
  to: "user@example.com",
  subject: "Your invoice is ready",
  html: "<p>Your March invoice is attached.</p>",
  tags: [{ name: "type", value: "invoice" }],
});

console.log(result.id); // SocketLabs message id
```

## Verify from the CLI

```bash
SOCKETLABS_API_KEY="..." npx --package @maillayer/core maillayer doctor --adapter socketlabs
```

```bash
npx --package @maillayer/core maillayer send \
  --adapter socketlabs \
  --from "Acme <alerts@acme.com>" \
  --to user@example.com \
  --subject "SocketLabs smoke test" \
  --text "It works" \
  --dry-run
```

Drop `--dry-run` to send for real. The adapter fails fast with an `EmailValidationError` if the message carries `metadata`, since the provider payload does not map that field.
