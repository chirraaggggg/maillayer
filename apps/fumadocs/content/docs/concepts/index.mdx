## Quick summary

**One message shape, one API.** Every adapter accepts the same `EmailMessage` and returns the same `EmailSendResult`. You configure the adapter once; call sites never change when you switch providers.

**Adapters are named routes.** `createEmailClient` derives a typed union of adapter names from the adapters you pass. Selecting an unknown name fails TypeScript; passing one at runtime throws `EmailAdapterNotFoundError`.

**Results are normalized.** `adapter`, `id`, `accepted`, and `rejected` come back in the same structure regardless of which provider handled the send.

**Errors are typed.** `EmailValidationError`, `EmailAdapterNotFoundError`, `EmailAdapterError`, and friends are distinct classes with structured fields — not strings to parse.
